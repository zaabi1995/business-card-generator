# Plan: Card Offers / Coupons Section

Port Infy vCard's "Coupon / Offers" feature into Cardify as a 6th public Card Section. Clean-room reimplementation following the existing PR #8 sections pattern.

## Goal
Card owners can attach time-limited offers ("10% off — show this card") to their digital card. Each offer renders as a colored badge with description, valid-until date, and an optional Redeem button that increments a counter and logs an analytics event.

## DB — migration `047_card_offers.php`

Table `employee_card_offers`:
- `id` VARCHAR(36) PK
- `employee_id` VARCHAR(36) FK → employees(id) ON DELETE CASCADE
- `company_id` VARCHAR(36) FK → companies(id) ON DELETE CASCADE
- `title` VARCHAR(255) NOT NULL
- `description` TEXT
- `discount_label` VARCHAR(64)  (e.g. "10% off", "BOGO", "Free delivery")
- `valid_from` DATE NULL
- `valid_until` DATE NULL
- `badge_color` VARCHAR(16) DEFAULT '#009bc1'  (BHD palette)
- `redemption_count` INT DEFAULT 0
- `enabled` TINYINT(1) DEFAULT 1
- `position` INT DEFAULT 0
- `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP
- INDEX (employee_id, position)

Also: `ALTER TABLE card_events MODIFY COLUMN event_type ENUM(... existing 11 ..., 'offer_redeem') NOT NULL`.

`section_order` already free-form CSV — `offers` slots in without schema change.

## Code

1. **`includes/CardSections.php`** — extend:
   - Add `'offers'` to `SECTION_KEYS`.
   - `loadOffers($employeeId, $publicOnly = false)` — when `$publicOnly`, filter `enabled=1` AND (`valid_until IS NULL OR valid_until >= CURDATE()`).
   - `addOffer($eid, $companyId, $title, $description, $discountLabel, $validUntil, $badgeColor)`.
   - `deleteOffer($eid, $offerId)`.
   - `incrementRedemption($eid, $offerId)` — atomic UPDATE `... SET redemption_count = redemption_count + 1`.
   - `saveMaster()` — accept `offers_enabled` field.

2. **`includes/CardAnalytics.php`** — append `'offer_redeem'` to `EVENT_TYPES`.

3. **`migrations/047_card_offers.php`** — table create + ENUM ALTER (idempotent: skip ALTER if column already contains `offer_redeem`).

4. **`company/views/employee.php`**:
   - Add 6th toggle "Offers" in section grid.
   - New POST actions: `add_offer`, `delete_offer`.
   - Repeatable rows: title, description, discount label, valid until (date), badge color (palette swatches: BHD blue/yellow/purple/teal/red/green), submit button.
   - List of existing offers with delete buttons + redemption count.
   - Add `offers` to default `section_order`.

5. **`digital_card.php`**:
   - Load `$sectionOffers = !empty($sectionMaster['offers_enabled']) ? CardSections::loadOffers($employee['id'], true) : [];`
   - Render `elseif ($__sec === 'offers' && ...)` block — card-grid: title, colored discount badge pill, description, "Valid until {date}", Redeem button → `/api/offer/redeem.php?oid={id}&eid={employee_id}`.
   - CSS: `.offer-card`, `.offer-badge`, `.offer-redeem-btn`.

6. **`api/offer/redeem.php`** (new file under `api/offer/`):
   - GET `?oid=<offer_id>&eid=<employee_id>`.
   - Validate offer belongs to employee, enabled, not expired.
   - `CardSections::incrementRedemption()` + `CardAnalytics::log($eid, $cid, 'offer_redeem', "offer:$oid")`.
   - Respond JSON `{ok: true, redemption_count: N}` if `Accept: application/json` else 302 back to card page.

## Tenant Scoping
- All admin actions verify employee belongs to logged-in `company['id']` (existing pattern in employee.php — actions filter by `$employeeId` from session).
- Public redeem endpoint validates offer's employee_id matches input eid (no cross-employee redemption).

## Validation
- `php -l` every modified/new file.
- Migration runs cleanly on local MySQL (test on VPS via direct `mysql` client per spec).
- Smoke: `curl /api/offer/redeem.php?oid=<real>&eid=<real>` → 302 + `redemption_count` increments in DB.

## Don't touch
- Fabric.js editor, Paymob, Wallet pass code.

## Out of scope
- Reordering offers (uses `position` for future).
- Per-offer image/photo.
- Offer claim codes / unique codes.
